# Retrieval contract

**Owner:** Piyush. **Consumers:** Atharv's evidence service, Vandit's adapters, Vanashree's coverage candidate search. **Version:** 1.0.0. The only public knowledge-search operation is `RetrievalService.search(request: SearchRequest) -> RetrievalRun` as defined in `16`. `search_semantic`, `search_lexical`, `hybrid_search`, `rerank` and `multi_document_search` are internal strategies, not separate public APIs. Callers request evidence through `VerityService.search_evidence`; they do not know which strategy ran.

The search request and result fields are exactly `03`. Query is trimmed, Unicode normalized NFC, and empty-after-trim is `INVALID_REQUEST`. `document_ids=null` searches all active, ready/partial documents; an explicit nonempty list searches only those documents. Unknown document IDs return `DOCUMENT_NOT_FOUND` rather than silently broadening scope. `document_kinds` and `chunk_kinds` are conjunctive filters. `per_document_limit` is optional and applied after global scoring, before final `limit`, preserving relative rank. Search uses active document versions only; historical chunks remain accessible through evidence resolution, not active search.

V1 branch budgets: up to 50 lexical and 50 semantic candidates after filters, RRF constant 60, at most 30 fused candidates passed to reranker, final `limit` 1–20. Branch ranks start at 1. Deduplicate by `chunk_id`. RRF is `sum(1/(60+rank))`; ties break by ascending `chunk_id`. Reranker receives the exact query and top 30 candidates; if available and successful, order by descending reranker score, then RRF, then `chunk_id`. Otherwise order by RRF and record `reranker_used=false`. The final `RetrievalResult.score` is the reranker score if used, else RRF score; scores are not probabilities or comparable across queries. BGE-M3 is the semantic provider; SQLite FTS5 is lexical; RRF/reranking belong entirely to retrieval. Exact model revision is config, not a hardcoded interface. A failed branch may degrade to `lexical_only` or `semantic_only` with `partial` and an omission; both failed is `RETRIEVAL_UNAVAILABLE`. A no-match successful query returns empty, never an error.

`RetrievalResult` contains the full `Chunk` and rank provenance; the EvidenceService constructs `Evidence`, `Citation` and `SearchResult`. Retrieval does not format citations or return raw DB rows to adapters. Ordering is stable for the same DB version, config and model outputs. V1 search has **no pagination**: bounded `limit` and explicit filters avoid cursor semantics during the hackathon. Document/source listings use offset pagination under `11`. Search timeout is 15 seconds excluding initial model provisioning, which is an operator step before serving. SQL is parameterized and FTS syntax escaped.

Errors: `INVALID_REQUEST`, `DOCUMENT_NOT_FOUND`, `MODEL_UNAVAILABLE` only when a required configured model prevents both branches, `RETRIEVAL_UNAVAILABLE`, `TIMEOUT`, `VERSION_UNSUPPORTED`. Errors use `17`. The implementation may choose vector scan/index, batch size, cache and tokenization internally as long as these ordering, budget and provenance properties hold.

This follows Mnemo's observed V2 dense+sparse → RRF(60) → bounded rerank path (`mnemo-core/mnemo/retrieval/full_multilingual_v2.py`). Mnemo's V1 `SQLiteStore.search_dense` is unimplemented; VERITY must supply its own semantic adapter rather than call that facade.
