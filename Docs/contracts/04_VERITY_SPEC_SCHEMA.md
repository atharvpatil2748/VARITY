# VERITY Spec Markdown 1.0.0

**Owner:** Piyush. **Consumers:** Atharv, Vanashree, Vandit. The spec format is only for author-declared verifiable documents. PDFs, TXT and arbitrary Markdown use general ingestion; a PDF is never automatically classified as a structured spec based on apparent `REQ` text.

The UTF-8 file starts with YAML front matter. Required keys: `verity_spec: "1.0.0"`, `source_key`, `project`, `title`, `spec_version`. `source_key` follows `03` slug syntax and is descriptive; the registered `source_id` is generated by persistence. Optional keys: `authors` string array and `language` BCP 47. Unknown front-matter keys are rejected in v1. `spec_version` is the author's version and does not change the parser contract version. Front matter has no date requirement.

Required top-level `# Requirements` with one or more `## REQ-###: Title` sections. Optional top-level `# API definitions`, `# Acceptance criteria`, `# References`, in that order after Requirements. A requirement begins with at least one nonempty normative paragraph, then optional `### Constraints`, `### Edge cases`, `### References` headings in that order. Under Constraints/Edge cases, each `- ` bullet is one string; nested bullets are invalid. Under References, each bullet is a local ID (`REQ-*`, `API-*`, `AC-*`). API definitions use `## API-###: Title` and text. Acceptance criteria use `## AC-###: Title`, nonempty text, then a required `References: REQ-001, REQ-002` line listing one or more existing requirements. `# References` may contain free text or links and yields general chunks, never requirements. Heading depth and ID/title separator are exact so parsing is deterministic.

Every `REQ-*`, `API-*`, `AC-*` ID is unique within its own namespace and spec version; duplicates or dangling references reject the full ingestion with `SPEC_VALIDATION_ERROR` and source line. Missing requirement ID, empty title/text, malformed heading, missing metadata, unsupported version, or unrecognized structured child heading also reject the full spec. No partial structured spec commit. The parser does not generate IDs or infer relationships. Requirement `text` excludes child heading content; `constraints` and `edge_cases` preserve bullet order. Acceptance criteria listed by reference become embedded `Requirement.acceptance_criteria` in authored order. Requirement `api_refs` and `reference_ids` are resolved locally. One primary requirement chunk contains title, text, constraints and edge cases; acceptance criteria and API definitions have separate chunks. `Requirement.locator` points to its heading and normative text span, and its primary `chunk_id` points to the generated chunk. All line numbers refer to the original UTF-8 Markdown line count starting at 1.

```markdown
---
verity_spec: "1.0.0"
source_key: payments-api
project: payment-service
title: Payment API Specification
spec_version: "1.0"
language: en
---

# Requirements
## REQ-001: Refund window
Refund requests MUST be accepted only within 30 days.

### Constraints
- A later request MUST return REFUND_WINDOW_EXPIRED.

### Edge cases
- A request at exactly 30 days is accepted.

### References
- API-001

## REQ-002: Partial refund
The API MUST support partial refunds.

# API definitions
## API-001: POST /refunds
Request fields are payment_id, amount and idempotency_key.

# Acceptance criteria
## AC-001: Late refund
A payment older than 30 days returns REFUND_WINDOW_EXPIRED.
References: REQ-001

# References
- Internal payments architecture, section 4.2.
```

The example produces two `Requirement`s, one API `SpecEntity`, one acceptance criterion attached to REQ-001, and separate retrieval chunks. Re-ingesting identical bytes under the same `source_id` is idempotent; changed bytes create a new `version_id` while `requirement_id` remains stable for unchanged local IDs. A deleted ID is absent from the active version but historical evidence still resolves against the old version. Parser errors use `SPEC_VALIDATION_ERROR` for authored shape and `VERSION_UNSUPPORTED` for `verity_spec` mismatch. Future format changes follow `02` and use an explicit new version value.
