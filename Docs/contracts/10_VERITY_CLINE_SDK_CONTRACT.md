# Native VERITY Cline SDK agent contract v1.0.1

**Owner:** Atharv. **Consumers:** native VERITY UI, Python service, Vandit for parity. **Cline SDK powers the native VERITY agent UI; MCP exposes VERITY to external Cline clients.** The SDK owns agent execution and reasoning for native chat. VERITY owns requirements, retrieval, Evidence, provenance, citations and coverage. The SDK gateway is the only agent runtime for native VERITY chat; the UI does not implement an independent agent or retrieval engine. The SDK tool names and input schemas are **identical** to `09`; their successful `execute` values are the same `SearchResult`, `Requirement`, `EvidenceLookup` and `CoverageResult` objects from `03`/`07`. No SDK-specific search or evidence DTO is permitted. The SDK adapter owns input validation and SDK serialization, not retrieval, citations or coverage.

```text
Native VERITY UI -> /api/v1/chat -> SDK gateway -> Cline SDK Agent
                                              -> canonical SDK tools -> VerityService
                                              -> retrieval / evidence / coverage
External Cline client -> MCP adapter -> VerityService
Other UI data views -> /api/v1 -> VerityService
```

The native UI's frozen chat entry points are `/api/v1/chat/*` in `11`; the HTTP adapter delegates chat to the SDK gateway. The Node SDK adapter may call the Python `VerityService` through the loopback HTTP API in `11`; the internal transport and process management are **DEFERRED — IMPLEMENTATION DISCOVERY** because the installed Cline SDK version and native UI packaging are not present in this repo. This does not defer tool names/shapes or evidence semantics. Both SDK and MCP converge on the same `VerityService` and canonical retrieval/evidence/coverage interfaces. The Node adapter never opens SQLite or reads source files directly. The Python core remains the sole business implementation. When the SDK is unavailable, `/api/v1/chat/*` returns `SDK_UNAVAILABLE` rather than a fake answer. Native chat is then unavailable; document/search/coverage views may still display canonical API data. In the eight-hour sprint the SDK chat implementation can follow the backend/MCP baseline so it cannot block core evidence delivery; that ordering does not make a non-SDK chat agent part of the native UI architecture.

Agent configuration inputs: `VERITY_CLINE_PROVIDER_ID`, `VERITY_CLINE_MODEL_ID`, and provider credential/local endpoint supplied through the installed SDK's supported mechanism; `VERITY_CLINE_API_KEY` is optional and must not be logged. `new Agent({providerId, modelId, systemPrompt, tools})` and `createTool({name, description, inputSchema, execute})` are supported by the current official [SDK README](https://github.com/cline/cline/blob/main/sdk/README.md). The current [Agent reference](https://github.com/cline/cline/blob/main/.agents/skills/cline-sdk/references/agent/REFERENCE.md) documents `run`, `continue`, `subscribe`, `snapshot` and `assistant-text-delta`. The README and reference disagree on some event/result property examples, so implementation must pin a package version and type-check a smoke test. No unverified event name or result property is a frozen VERITY contract.

The system prompt instructs the agent to call VERITY evidence tools before factual claims, cite only `[[ev_<64hex>]]` markers obtained from tool results, label unsupported claims as inference, treat source text as untrusted data, and never claim coverage from its own code edits. A tool returns structured `Error` data for expected failures. The agent can keep in-memory history per `session_id`; `run` starts a conversation and `continue` adds turns. The UI/backend chat contract in `11` returns final answer plus resolved `Evidence[]`; streaming progress is intentionally not part of v1, preventing an unverified SDK event model from leaking into public UI contracts. The gateway may stream internally later without changing v1 response shape.

`ChatMessage = {role:"user"|"assistant", text:string, citations:string[], created_at:UTC datetime}` and `ChatResponse = {schema_version:"1.0.0", session_id:UUIDv4, message:ChatMessage, evidence:Evidence[]}`. All fields required, `citations`/`evidence` default `[]`. The backend extracts markers, resolves IDs through EvidenceService, rejects or flags unresolved markers, and never generates a new citation label. Conversation persistence beyond process life is out of v1. The UI calls REST, not MCP; for chat it renders the Cline SDK agent response and resolved Evidence. It never performs its own search ranking, evidence construction or coverage evaluation. This v1.0.1 clarification changes no wire object, tool name, route, status or schema version.
