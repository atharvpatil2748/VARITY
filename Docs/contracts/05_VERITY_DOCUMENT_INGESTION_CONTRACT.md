# General document ingestion contract

**Owner:** Piyush for parsing/chunking; Atharv for persistence. **Consumers:** retrieval and UI. **Version:** 1.0.0. The public flow is original bytes → parser → `ParsedDocument` → chunker → `ChunkDraft`s → central materializer → `Chunk`s → SQLite/FTS/embedding. Parsers do not persist or call models.

`IngestRequest = {source_path: relative string, mode: auto|spec|general, source_id: UUIDv4|null}`. All fields required; `mode` defaults `auto`, `source_id` defaults null. `auto` treats Markdown with exact `verity_spec` front matter as spec and other supported files as general; malformed front matter that begins `verity_spec` is a spec error, never silently general. `source_id` means reingest that registered source; null registers a new source. API upload supplies bytes separately. Supported MVP inputs are PDF (`application/pdf`), Markdown (`text/markdown`), TXT (`text/plain`) and code extensions `.py`, `.js`, `.ts`, `.tsx`, `.java` as `text/x-code`; unsupported types return `UNSUPPORTED_FORMAT`. HTML, DOCX, slides, OCR and images are deferred. A scanned/image-only PDF is `partial` with an extraction warning if any usable page exists, otherwise `PARSER_ERROR`.

`ParsedDocument = {metadata: DocumentMetadata, blocks: ParsedBlock[], media_type: string, kind: DocumentKind, spec_requirements: SpecRequirementDraft[], spec_entities: SpecEntityDraft[]}`. Both draft arrays are required and empty for general documents. `ParsedBlock = {ordinal: integer >=0, text: nonempty string, block_type: paragraph|heading|code, page: integer>=1|null, heading_path: string[], start_line/end_line: integer>=1|null, start_offset/end_offset: integer>=0|null}`. All properties required; null location fields are explicit. Ordinals are contiguous from zero. Page and line/offset semantics follow `03`. PDF block page must be known; Markdown/TXT/code page is null. Source code must have line positions. Parser warnings are stored in `DocumentMetadata.warnings`. Parser implementations may differ internally but must meet these guarantees. Spec draft types are defined in `03`; only the materializer assigns source/document/version/requirement/chunk/evidence IDs.

`ChunkDraft = {kind: ChunkKind, text: nonempty string, block_start: integer>=0, block_end: integer>=0, start_offset: integer>=0|null, end_offset: integer>=0|null, requirement_id: req-hash|null}`; all properties required. Drafts are ordered and cite only a contiguous valid block span. Chunker must not span pages, and must not invent a page/line. Central materializer assigns the `Locator`, `ordinal`, `chunk_id` and `schema_version`; chunkers never assign IDs. Spec parser emits requirements before chunking; requirement chunks use the explicit `requirement_id`. General Markdown/TXT/PDF chunks use `general_chunk`; code uses `code_chunk`. A chunk may combine blocks under one heading/page. Target token size, overlap and code symbol heuristics remain internal choices. The original text must be recoverable or the parser marks a warning/partial status.

`Parser.parse(data: bytes, filename: str, media_type: str) -> ParsedDocument` and `Chunker.chunk(parsed: ParsedDocument, version_id: UUID) -> tuple[ChunkDraft,...]` are exact cross-module signatures in `16`. The ingestion coordinator validates maximum bytes, media type, UTF-8 where needed, and path before calling parsers. After parsing, it calls `KnowledgeStore.prepare_ingestion` to obtain stable source/document IDs and the new/existing version ID without writing; after materialization, `activate_ingestion` commits everything atomically. Parser errors: `UNSUPPORTED_FORMAT`, `PARSER_ERROR`, `SPEC_VALIDATION_ERROR`, `VERSION_UNSUPPORTED`. Chunker errors: `CHUNKING_ERROR` for invalid spans/empty output when parsed text exists. `ingest` returns `Document` plus `created_new_version: boolean`; it is idempotent for the same source and content hash. Indexing failures set `DocumentStatus.partial` and report an omission while retaining lexical data; canonical parsing/DB transaction failure leaves prior active version untouched. The materializer resolves draft block ranges to canonical locators, validates referenced local IDs, creates final requirements/entities/chunks and passes them as one batch to storage.

Mnemo's actual parser protocol accepts bytes and metadata, and its V2 chunker emits drafts before central ID assignment (`mnemo-core/mnemo/interfaces/{parser,chunker}.py`, `chunkers/dispatcher.py`). VERITY adopts that boundary, with a deliberately smaller normalized block model and format set.
